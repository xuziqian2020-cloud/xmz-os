# 本地会议纪要设计

## 目标

将“会议纪要”改为完全在本机运行：FunASR 负责音频转文字与说话人区分，Ollama 中的 `qwen3:4b` 负责将转写文本整理为会议纪要。整个流程不调用 DeepSeek 或其他付费 AI API。

## 范围

- 支持会议录音结束后的本地转写。
- 支持按发言人输出转写文本；当转写服务未返回发言人信息时，保留正常文本并明确提示。
- 支持使用本地 Qwen3 生成会议纪要与现有 Word 下载文件。
- 在 AI 设置中区分“音频转写”和“文本/纪要”两种用途的服务。

第一版不实现真正的本地流式实时转写。现有浏览器 `SpeechRecognition` 仅作为可选辅助，不应影响录音后转写主流程。

## 本地服务

### 音频转写服务

- 服务：FunASR。
- 默认地址：`http://127.0.0.1:8000/v1`。
- 默认模型：`sensevoice`。
- 接口：`POST /audio/transcriptions`。
- 能力：中文转写、时间分段、说话人区分。

FunASR 未启动、地址不可访问、模型不可用或未返回有效文字时，前端应得到可理解的中文错误提示，不得将失败结果提交给纪要模型。

### 会议纪要服务

- 服务：Ollama。
- 地址：`http://127.0.0.1:11434/v1`。
- 默认模型：`qwen3:4b`。
- 接口：`POST /chat/completions`。
- API Key：本地兼容接口使用占位值 `ollama`。

纪要服务仅接收转写完成后的文字与会议主题、参会人信息，不接收原始音频。

## 服务选择规则

现有实现只会选中一个 AI 供应商，无法同时对应 FunASR 和 Ollama。现有 `ai_providers` 表没有用途字段，本次不增加数据库字段或迁移，两个本地服务均使用现有的“自定义兼容供应商”记录，并按固定配置识别用途：

| 用途 | 识别规则 | 选择规则 |
| --- | --- | --- |
| 音频转写 | 地址为本地 FunASR 地址且模型为 `sensevoice` | 仅用于 `/api/tools/transcribe` |
| 文本/纪要 | 非音频转写供应商，例如本地 Ollama 的 `qwen3:4b` | 仅用于 `/api/tools/meeting-minutes` 及原有聊天功能 |

已有供应商默认作为文本/纪要供应商处理，以保持原有聊天、AI 秘书等能力不变。AI 设置新增 FunASR 与 Ollama 预设，并允许同时启用多个供应商。会议页面分别传入音频供应商和纪要供应商，服务端仍沿用现有安全校验与请求转发模式。

## 数据流程

1. 用户开始、停止会议录音，页面取得 WebM 音频。
2. 页面向 `/api/tools/transcribe` 提交音频、音频供应商和 `sensevoice` 模型。
3. 路由转发请求到 FunASR 的 `/v1/audio/transcriptions`，请求说话人区分。
4. 路由标准化 FunASR 返回的 `segments`：有发言人时输出“发言人 N：文本”，没有发言人时输出文本并返回提示。
5. 用户点击“生成纪要”，页面向 `/api/tools/meeting-minutes` 提交转写文本和聊天供应商。
6. 路由调用本地 Ollama 的 `/v1/chat/completions`，复用现有会议纪要提示词与 Word HTML 生成逻辑。

## 错误处理

- 未配置音频供应商：提示在 AI 设置添加并启用 FunASR 音频转写服务。
- FunASR 服务不可达：提示检查本地服务是否已启动及地址是否为 `127.0.0.1:8000`。
- 音频未识别出文字：禁止生成纪要，并提示检查录音内容。
- 没有说话人数据：允许继续生成纪要，同时提示当前转写未返回发言人区分。
- 未配置纪要供应商或 Ollama 模型不可达：提示检查 Ollama、`qwen3:4b` 与 AI 设置。

## 测试

- 供应商选择：音频用途只能选择 `audio` 供应商，纪要用途只能选择 `chat` 供应商，旧配置默认聊天用途。
- 转写请求：页面与路由使用 `sensevoice`，不再固定 `whisper-1`。
- 转写解析：覆盖有发言人、无发言人和空返回三种情况。
- 路由：验证转写与纪要各自调用对应供应商，不会互相串用。
- 回归：现有聊天供应商选择与会议纪要 Word 输出保持可用。

## 成功标准

在同一台 Windows 电脑上启动 FunASR 和 Ollama 后，用户完成一段录音即可获得带发言人标记的文字，并能生成中文会议纪要与 Word 文件；全程不需要 DeepSeek API Key 或其他付费 AI API。
